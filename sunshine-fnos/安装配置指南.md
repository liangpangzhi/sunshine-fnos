# Sunshine 串流 fpk 安装与配置指南（v3.2.0 · 任意应用地址 + NVENC 版）

> 飞牛 NAS（192.168.5.11）运行 Sunshine，把 **安装时填写的任意应用地址**（如飞牛影视 `http://192.168.5.11:5666`、DecoTV、NAS 管理页）画面+声音串流到电视（192.168.5.6），换应用不用重装。
> **本版已内置完整运行镜像，安装零联网、无需 docker build。**

---

## 〇、v3.2.0 新增：串流任意应用

### 安装时填地址

应用中心安装 fpk 时会弹两页向导：

| 字段 | 环境变量 | 说明 |
|------|----------|------|
| 应用地址 | `wizard_app_url` | 任意 Web 应用地址；不写 `http://` 会自动补；含空格/缺主机名会被拒绝安装 |
| 应用名称 | `wizard_app_title` | 只影响显示（控制台标题） |
| 打开方式 | `wizard_mode` | `kiosk` 全屏无地址栏 / `browser` 窗口+地址栏 / `desktop` 仅虚拟桌面 |
| 虚拟桌面分辨率 | `wizard_resolution` | `1920x1080` / `1280x720`（Xvfb 实际分辨率） |

安装脚本 `cmd/install_init` 会校验地址、写 `docker/app.env`，并同步一份持久配置到 `var/app.conf`。

### 装好后换应用（不用重装）

桌面「**串流控制台**」→ `http://NAS-IP:47991`：

- 改地址 / 名称 / 打开方式 → **保存并切换**：`start.sh` 每 2 秒轮询配置，Chromium 自动重启到新地址（约 2 秒）
- 状态标签：地址可达 / 不可达、浏览器运行中、当前虚拟分辨率
- 预设按钮：DecoTV、飞牛影视、飞牛管理页
- `GET /api/status` 返回 JSON（便于脚本/自动化检查）

### 配置优先级

```
/appdata/app.conf（控制台修改，挂载自 /var/apps/sunshinestream/var）
  > docker/app.env（安装/升级向导写入）
  > 内置默认值
```

- 升级时向导留空 → 沿用上次地址（含运行期改过的）
- 升级时向导填了新地址 → 以新地址为准
- `seed` 字段记录「上次向导写入的值」，用来区分「向导变更」与「运行期修改」，避免互相覆盖

## 二、你还需要做的三步

1. **设置 Sunshine 账号**：浏览器打开 `https://192.168.5.11:47990`（自签证书点「继续访问」），设置用户名密码并登录。
2. **电视装 Moonlight**：索尼电视（Google TV）在 Play 商店搜索 **Moonlight Game Streaming** 安装；搜不到就用 APK 侧载（GitHub `moonlight-android.apk`）。
3. **配对**：Moonlight → 手动添加主机 `192.168.5.11` → 电视显示 4 位 PIN → 在 47990 网页的 PIN 页面输入 → 完成。

Moonlight 推荐设置：**1920×1080 / 60 FPS / 30~50 Mbps / H.264（最稳）或 HEVC 8-bit**。

## 三、本次排查记录（重要，避免重复踩坑）

| 现象 | 根因 | 处理 |
|------|------|------|
| 安装中途失败 `APP_INSTALL_FAILED_INIT_DOCKER_EXCEPTION` | fnOS 安装时先执行 `docker compose build`，BuildKit 去 `registry-1.docker.io` 拉基础镜像超时 | 改为**预构建完整镜像** `sunshine-stream:latest` 随包分发，安装阶段不再触发 build；`cmd/main` 启动时 `docker load` |
| 容器 `exec /start.sh: no such file` | 离线层把 `/bin /lib /sbin /lib64` 写成了真实目录，覆盖了 bookworm 的 usrmerge 符号链接（`/bin -> usr/bin`） | 组装层时把这 4 个前缀重写为 `usr/`，并去重 |
| `sway` 启动失败 | sway 拒绝以 root 运行（`Unable to drop root`），且检测到 NVIDIA 专有驱动 | 放弃 sway，改用 **Xvfb + X11 捕获**（`capture = x11`），更稳且与 NVIDIA 驱动无关 |
| `encoder = vaapi` 失败 | P620 是 NVIDIA，无 VAAPI | 改为 `encoder = nvenc` + compose 加 `runtime: nvidia`、`NVIDIA_DRIVER_CAPABILITIES=all` |
| 应用打不开 | 早期版本把网页地址写死在启动脚本里（`DECO_URL`），端口一变就白屏 | 已改为安装向导填写 + 控制台可改（v3.2.0），地址错了在向导阶段就会拦下 |

## 三点五、本机 USB 鼠标 / 键盘

虚拟桌面是 Xvfb，**它本身不读取任何输入设备**。为了让插在 NAS 上的 USB 鼠标键盘能操作串流画面，镜像内置了 `mouse-bridge.py`（evdev → XTEST 桥接）：

- 启动时自动接管 `/dev/input` 下的物理鼠标与键盘，支持热插拔（每 2 秒重扫）
- 鼠标移动/左右中键/滚轮、键盘按键都会注入到 `:99` 虚拟桌面
- 会自动排除 Sunshine 自己的虚拟设备（名字含 `passthrough`），避免输入端翻倍
- 日志：`docker exec sunshine-stream cat /var/log/mouse-bridge.log`

自测方式（会移动指针 160px，正常应打印 PASS）：

```bash
docker cp 测试脚本 sunshine-stream:/tmp/t.py
docker exec -e DISPLAY=:99 sunshine-stream python3 /tmp/t.py
```

## 三点六、桌面图标与延迟优化（v2.6.0）

- **桌面图标**：安装后飞牛桌面会出现「Sunshine 串流」图标，点击直接打开 `https://NAS-IP:47990` 后台（首次需接受自签证书）。配置见 `app/ui/config`。
- **输入延迟优化**：
  - 修复桥接 bug：键盘/点击事件之前未 `disp.sync()`，会滞留缓冲区直到鼠标移动才刷出（这就是"输入后很久才显示"的主因）
  - `minimum_fps_target = 60`：原来默认是客户端帧率的一半（30fps 客户端 → 15fps、66ms 一帧），现在强制 60fps 出帧
  - 建议 Moonlight 端也设 60 FPS
- **音频修复（三个叠加问题）**：
  1. `stream_audio = false` —— 串流音频开关被关掉，导致完全没有声音（启动脚本已强制为 true）
  2. `audio_sink` 指向 `virtual_speaker`，而 Sunshine 会把默认 sink 切到自建的 `sink-sunshine-stereo` → 抓错声卡，静音（已删除该配置，让它抓自己设置的 sink）
  3. 容器重启后 `/run/pulse` 残留旧 pid/socket，PA 报 `Daemon already running` 起不来（启动时先清理）
  另加了一个守护循环，新出现的音频流会自动跟随当前默认声卡
- **账号持久化**：`HOME=/config`，Sunshine 的账号/配对信息存进数据卷，重装或重启容器不再丢失

### 常见问题

| 现象 | 处理 |
|------|------|
| 串流黑屏 | `docker exec sunshine-stream tail -30 /var/log/xvfb.log`，确认 `DISPLAY=:99` 有窗口（`xwininfo -root -children`） |
| 画面是「This site can't be reached」 | 应用地址不通。打开 `http://NAS-IP:47991` 看「地址不可达」，改成本机可访问的地址；注意容器用 host 网络，地址要写 NAS 能访问的 IP:端口 |
| 改成别的应用后画面没变 | 看 `docker logs sunshine-stream \| grep 串流目标变更`；确认 `/var/apps/sunshinestream/var/app.conf` 已更新 |
| 控制台 47991 打不开 | `docker exec sunshine-stream tail -20 /var/log/console.log`；端口可能被占用 |
| 没有声音 | `docker exec sunshine-stream pactl info`；确认应用页面未静音；日志出现 `Couldn't set default-sink ... Timeout` 说明 D-Bus 没起来 |
| 输入延迟大 | 确认 `/config/sunshine.conf` 有 `minimum_fps_target = 60`；Moonlight 设 60fps；确认桥接日志有"接管keyboard" |
| 鼠标点不动 | X11 走 XTEST，`ldconfig -p | grep Xtst` 应存在；Moonlight 内开启「鼠标模式/触控板」 |
| 卡顿 | Moonlight 降到 H.264、码率 30 Mbps；电视有线连接 |
| HEVC 不可用 | P620 只支持 8-bit HEVC，Moonlight 里选 H.264 即可 |

## 五、包内结构

```
sunshinestream.fpk（约 531 MB）
├── manifest / config/privilege / config/resource
├── ICON.PNG / ICON_256.PNG
├── wizard/install  # 安装向导（应用地址 / 名称 / 打开方式 / 分辨率）
├── cmd/  main(启停+load镜像) install_init(校验地址+写 app.env/app.conf+load镜像) ...
└── app.tgz
    ├── docker/docker-compose.yaml   # host 网络 + privileged + nvidia runtime + /dev/dri + 脚本外挂
    ├── docker/app.env               # 安装向导写入的串流目标
    ├── docker/start.sh              # 配置加载 → PulseAudio → uinput → Xvfb → 浏览器守护 → Sunshine(NVENC)
    ├── docker/console.py            # 串流控制台（47991）
    ├── docker/sway-sunshine.conf    # 备用（当前用 Xvfb 方案）
    └── images/sunshine-stream.tar.gz (527MB)  # 完整镜像，docker load 即用
```

## 六、安全提示

- 47990 管理页与串流端口仅限家庭内网，不要暴露公网。
- 容器使用 `privileged` + `runtime: nvidia` + host 网络（设备访问 / mDNS 需要），仅在受信任 NAS 上使用。
